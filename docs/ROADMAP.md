Ревизия кода v0.9.9 от 14.11.2026. Документ — план устранения дефектов и доработок.

## 0. Как пользоваться этим документом (для исполнителя-модели)

1. Бери **одну задачу за раз**, строго по порядку внутри этапа. Этапы идут по порядку: 0 → 1 → 2 → 3 → 4 → 5 → 6.
2. В задаче указаны: файл и строка, что не так, шаги, критерий готовности. Делай только то, что написано в шагах. Не рефактори соседний код.
3. После каждой задачи: `npm test`. Все тесты должны проходить. Если в задаче написано «добавь тест» — добавляй в `test/index.test.js` в стиле существующих (`node:test`).
4. Одна задача = один коммит. Сообщение: `fix(T1.3): краткое описание`.
5. Номера строк даны для v0.9.9. Если строка сдвинулась — ищи по имени функции.
6. Не меняй `templates/Протокол.docx`, не меняй имена плейсхолдеров в `backend/protocol/placeholderMap.js`.
7. Перед началом: `npm install` (папки `node_modules` в поставке нет), затем `npm test` — зафиксируй исходное состояние.
8. Задачи с пометкой **[РЕШЕНИЕ ВЛАДЕЛЬЦА]** не начинай, пока в разделе 9 не записан ответ.

Приоритеты: **P0** — сломано или опасно, чинить до любого релиза; **P1** — неверные данные или потеря данных; **P2** — заметные дефекты; **P3** — долг.

Общие хелперы, которые вводятся в этапе 1 и используются дальше:

- `backend/utils/dateUtils.js` → `todayLocal()` — локальная дата `YYYY-MM-DD`; `isIsoDate(s)` — проверка формата и реальности даты.
- `app/renderer/app.js` → `esc()` (уже есть), `todayStr()` (добавить).

### T1.3 [P0] Шифрование базы
**Проблема (три дефекта сразу).**
- `main.js:295-296`: `setDbPassword` сохраняет пароль и новую соль, но ключ текущего сеанса считается `deriveKey(password)` **без соли** (SHA-256). При следующем запуске `getRuntimeKey` считает ключ **с солью** (PBKDF2). Ключи разные.
- Существующая открытая база нигде не перешифровывается (`rekey` не вызывается).
- `connection.js:25-28` передаёт ключ как опцию конструктора `{ key }`. В документации `better-sqlite3-multiple-ciphers` ключ задаётся через `db.pragma("key='…'")`. Возможно, опция игнорируется и база вообще не шифруется.
**Шаги.**
1. Сначала тест-проверка: создать временную базу с `new Database(path, { key: "abc" })`, записать таблицу, закрыть; прочитать первые 16 байт файла. Если это `SQLite format 3\0` — шифрования нет. Результат записать в раздел 9.
2. В `connection.js` `openDb`: убрать `options.key`; после открытия, если `runtimeDbKey` задан, выполнить `db.pragma("cipher='sqlcipher'")` и ``db.pragma(`key="x'${runtimeDbKey}'"`)`` (ключ — 64 hex-символа), затем проверочный `db.prepare("SELECT count(*) FROM sqlite_master").get()` в `try`; при ошибке закрыть базу и бросить `Error("Не удалось открыть базу: неверный пароль или база повреждена")`.
3. В `main.js` `security:enableDbPassword`: (а) сделать резервную копию `createLocalBackup({reason:"before_encrypt"})`; (б) сгенерировать соль, посчитать `key = deriveKey(password, salt)`; (в) открыть базу текущим ключом и выполнить ``db.pragma(`rekey="x'${key}'"`)``; (г) только после успеха сохранить пароль и соль в хранилище и вызвать `setRuntimeDbKey(key)`. Для этого изменить `dbPassword.setDbPassword(password, salt)` — соль принимать параметром.
4. `security:disableDbPassword`: резервная копия → `db.pragma("rekey=''")` → очистить хранилище → `setRuntimeDbKey(null)`.
5. Проверка длины пароля: меньше 8 символов — ошибка.
6. Тест: включить пароль → закрыть → открыть заново с ключом из `getRuntimeKey` → данные читаются; без ключа — ошибка открытия.
**Готово, когда:** после включения пароля и перезапуска приложение открывает базу; файл базы не начинается с `SQLite format 3`.
**Ограничение, которое нужно показать в интерфейсе:** соль и пароль хранятся в системном хранилище одного компьютера. На втором компьютере зашифрованную базу с FTP открыть нельзя, пока там не введён тот же пароль. Соль поэтому надо хранить рядом с базой (файл `eb_protocols.salt` в папке данных и на FTP), а не в хранилище — сделать это в этой же задаче.

- Тарифы: «Персональная» 499 ₽/год, «Организация» 1500 ₽/год. Оплата пока вручную, код по почте.

### 7.2 Рекомендация
Перенести ту же модель без изменений: **офлайн-код + окно ожидания, функции не блокируются.**

Почему: программа открытая (MIT) и заявлена на сайте как бесплатная — жёсткую блокировку уберут одной правкой, а обещание на лендинге будет нарушено. Сервер активации потребует обработки персональных данных и поддержки. Один формат кода позволяет использовать тот же инструмент выдачи и ту же оферту.

**[РЕШЕНИЕ ВЛАДЕЛЬЦА] — три вопроса, ответы в раздел 9:**
1. **Один код на оба продукта или отдельные?** Рекомендую один: тот же ключ, тот же формат, покупатель «Реестра» получает «Протокол ЭБ» без окна ожидания. Отдельные коды потребуют нового поля `p` (продукт) и версии формата 2 в обоих приложениях.
2. **Где показывать окно ожидания.** Предложение: 10 с при запуске раз в сутки; 20 с перед сохранением протокола, начиная с 11-го протокола в календарном году; 30 с перед синхронизацией по FTP.
3. **Что даёт тариф «Организация» сверх «Персональной».** В «Реестре» — несколько организаций. Здесь организация одна. Предложение: «Персональная» снимает ожидание при запуске и сохранении; «Организация» дополнительно снимает ожидание перед синхронизацией (работа нескольких компьютеров с одной базой).

### 7.3 Задачи

**T5.1 Модуль проверки кода — `backend/license/license.js`.**
```js

function parseCode(code, today /* YYYY-MM-DD */) { … }
```
Шаги `parseCode`: убрать все пробельные символы; пусто → `Error("Введите код лицензии")`; длина > 2000 → ошибка; разбить по `.`; частей не 3 или первая не `NOT1` → `Error("Неверный формат кода лицензии")`; `payloadBytes = b64url(parts[1])`, `sig = b64url(parts[2])`; ключ: `crypto.createPublicKey({ key: Buffer.concat([SPKI_PREFIX, Buffer.from(PUBLIC_KEY_B64, "base64")]), format: "der", type: "spki" })`; `crypto.verify(null, payloadBytes, key, sig)` ложно → `Error("Код лицензии недействителен")`; `JSON.parse(payloadBytes.toString("utf8"))`; `v !== 1` → `Error("Код выпущен для другой версии программы")`; `t` не из `org|personal` или пустое `n` → ошибка формата; `exp < today` (сравнение строк) → `Error("Срок действия лицензии истёк ДД.ММ.ГГГГ")`. Вернуть `{ tier, holder, expires, codeId }`.
**Важно:** подпись проверяется по исходным байтам payload. JSON заново не сериализовать.
Тесты: взять 3 кода из `Excel_to_XML-main/tests/test_license.py` (верный, с испорченной подписью, просроченный) — результат должен совпасть с Python.

**T5.2 Хранение.** `backend/license/licenseStore.js`: `activate(code)` → `parseCode` → сохранить код через хранилище секретов (ключ `license_code`; после T4.6 — `safeStorage`) → вернуть лицензию. `getLicense()` — прочитать, проверить, вернуть лицензию или `null`; результат кэшировать на время работы процесса. `clear()`. Имя владельца в журнал событий не писать (персональные данные) — только тариф, срок, идентификатор.

**T5.3 Защита от перевода часов.** В `settings` хранить `license.last_seen_date`. При каждой проверке: если `todayLocal() < last_seen_date` — считать текущей датой `last_seen_date`; иначе обновить. В «Реестре» этого нет — перенести туда тем же способом.

**T5.4 Каналы.** `license:get` → `{ active, tier, holder, expires, daysLeft }`; `license:activate(code)`; `license:clear`; `license:nagState(kind)` → `{ waitSeconds }`. Добавить в `preload.js`. **T5.5 Состояние «раз в сутки».** `settings`: `license.nag_last_shown = YYYY-MM-DD`. Ожидание при запуске показывается, если дата не сегодняшняя.

**T5.6 Интерфейс.** Модальное окно: заголовок «Поддержите разработку», текст о тарифах, ссылка на `https://normaot.ru/license.html` (открывать через `shell.openExternal` с проверкой, что адрес начинается с `https://normaot.ru/`), поле ввода кода, кнопка «Активировать», кнопка «Продолжить» — неактивна, пока идёт обратный отсчёт. В настройках — блок «Лицензия»: тариф, владелец, срок, кнопки «Ввести код» и «Удалить код». За 30 дней до окончания — строка «Лицензия истекает через N дней».

**T5.7 Инструмент выдачи.** При одном коде на оба продукта — ничего не менять, использовать `Excel_to_XML-main/tools/license_tool.py`. При раздельных — добавить ключ `--product` и поле `p`.

**T5.8 Сайт и документы.** `license.html`, `oferta.html`: добавить «Протокол ЭБ» в предмет лицензии и описать окно ожидания. `protokoly-eb.html`: формулировку «бесплатно» уточнить — «бесплатно, все функции доступны; лицензия убирает окно ожидания». README и CHANGELOG. Заодно устранить расхождение «Реестра»: README — «раз в день», `license.html` — «при запуске».

**T5.9 Чего не делать.** Не блокировать функции. Не добавлять сервер активации и привязку к компьютеру. Не отправлять никаких данных по сети. Не хранить закрытый ключ в репозитории.
